Digital Wallet
Ein persönliches Lern- und Entwicklungsprojekt rund um moderne
Softwareentwicklung -- Schritt für Schritt, mit Fokus auf Verständnis
statt Copy & Paste.
Projektstatus: In Entwicklung · Backend zuerst · Frontend
später

Warum dieses Projekt?
Vor etwa eineinhalb Jahren wollten meine Frau und ich auf Mallorca zwei
Kaffees und zwei Croissants bestellen. Ich versuchte zweimal, kontaktlos
mit meiner digitalen Karte zu bezahlen. Beide Male zeigte das Terminal
die spanische Meldung „Operación denegada" mit einem roten Kreuz. Der
Cafébesitzer bestätigte, dass die Zahlung fehlgeschlagen sei. Da unser
Bargeld nicht für die gesamte Bestellung reichte, nahmen wir nur zwei
Kaffees und bezahlten bar.

Zurück in Deutschland stellte ich fest, dass beide Kartenzahlungen
trotzdem abgebucht worden waren.

Diese Erfahrung hinterließ eine technische Frage: Was passiert hinter
den Kulissen einer digitalen Zahlung -- und wie lassen sich solche
Probleme zuverlässig behandeln?

Dieses Projekt ist mein Weg, mich mit diesen Fragen auseinanderzusetzen
und mein Wissen in der Softwareentwicklung systematisch zu vertiefen.
Ziele
- Java und Spring Boot anhand eines zusammenhängenden Projekts besser
  verstehen.
- Sauberen, nachvollziehbaren und wartbaren Code schreiben.
- Technische Entscheidungen bewusst treffen und begründen können.
- Tests, Fehlerbehandlung, Datenpersistenz und Transaktionskonzepte
  praktisch kennenlernen.
- Schritt für Schritt ein Gefühl dafür entwickeln, wie zuverlässige
  Softwaresysteme aufgebaut werden.
- Erkenntnisse und Themen teilen, die ich auf diesem Lernweg für
  wichtig halte.
Das Projekt ist in erster Linie ein Lernprojekt. Es ist keine echte
Zahlungsplattform und verarbeitet keine realen Zahlungen.
Geplanter Technologie-Stack
Backend -- zuerst
- Java 21
- Spring Boot
- Maven
- PostgreSQL
Frontend -- später
- React
- TypeScript
Die Umsetzung erfolgt schrittweise. Der genaue Funktionsumfang und
Zeitplan entwickeln sich mit dem Lernfortschritt.
Geplanter Lern- und Entwicklungsweg
Die folgenden Punkte sind eine Orientierung und keine Behauptung, dass
diese Funktionen bereits implementiert sind.
- [ ] Projektstruktur und Grundlagen des Backends aufbauen
- [ ] Java- und Spring-Boot-Konzepte praktisch anwenden
- [ ] REST-API und sinnvolle Fehlerbehandlung entwickeln
- [ ] Unit- und Integrationstests ergänzen
- [ ] Daten mit PostgreSQL persistieren
- [ ] Transaktionen und den Umgang mit wiederholten Anfragen
  untersuchen
- [ ] Relevante Sicherheitsaspekte kennenlernen
- [ ] Später ein Frontend mit React und TypeScript ergänzen
- [ ] Architektur und Entscheidungen fortlaufend dokumentieren
Die Reihenfolge kann sich ändern, wenn sich beim Lernen neue Fragen oder
bessere Ansätze ergeben.
Mein Ansatz: verstehen, selbst schreiben, kritisch prüfen
Ich möchte den Code selbst schreiben und die Konzepte dahinter
verstehen, statt Lösungen einfach zu übernehmen.

LLMs nutze ich als Lernbegleiter: zum Erklären von Konzepten, zum
Hinterfragen technischer Entscheidungen und als Unterstützung beim
Lernen. Ihre Vorschläge prüfe ich kritisch. Denn hilfreiche Antworten
ersetzen nicht das eigene Wissen und die Fähigkeit, die Korrektheit
einer Lösung zu beurteilen.

Mein Ziel ist nicht, möglichst schnell möglichst viel Code zu
produzieren, sondern eine solide Grundlage aufzubauen.
